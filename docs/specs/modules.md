# Module Architecture Spec

**Status:** Canonical (`foundation-v1`)  
**Scope:** Vertical feature modules under `main/modules/<id>/`, manifest declarations, server & web bindings, and DAG rules.

---

## 1. Purpose

Every product or platform domain capability in BSLT lives in a single self-contained vertical module at `main/modules/<id>/` (`@bslt/<id>`) and is registered in [`bslt.config.ts`](../../bslt.config.ts). Installing, removing, or reading a feature never requires editing scattered horizontal registries across `apps/server`, `apps/web`, or kernel packages.

---

## 2. Canonical Directory Shape

Enforced at merge time by the `module-shape` gate (`main/tools/gates/module-shape.ts`):

```text
main/modules/<id>/
├── package.json              # @bslt/<id> — exports ./module, ./contract, ./server, ./web
├── tsconfig.json             # Extends @bslt/build-config/tsconfig.module.json
├── vitest.config.ts          # Extends @bslt/build-config/vitest
├── README.md                 # Hand-written intro + <!-- bslt:generated reference --> block
├── module.ts                 # defineModule({ id, summary, status, dependsOn, ... })
├── contract/
│   ├── index.ts              # Public contract exports (schemas, endpoints, errors, events, api)
│   ├── schemas.ts            # @bslt/schema combinator definitions + Infer<typeof ...> types
│   ├── errors.ts             # defineErrors('<id>', { CODE: httpStatus })
│   └── endpoints.ts          # endpoint({ method, path, auth, params, query, body, response, errors })
├── server/
│   ├── index.ts              # implementServer(<id>Module, (k, deps) => ({ endpoints, ... }))
│   ├── service.ts            # Domain business logic over TransactionContext / KernelServices
│   ├── repository.ts         # SQL queries over generated rows & column maps
│   ├── migrations/
│   │   └── 0001_<id>.sql     # Append-only SQL baselines (<id>_ table prefix + sys_apply_rls)
│   └── generated/
│       ├── rows.ts           # Generated by `pnpm bslt sync rows`
│       └── rls.real-db.test.ts
├── web/                      # Omitted only when `web: false` in module.ts
│   ├── index.ts              # implementWeb(<id>Module, { routes, nav, settings, admin, ... })
│   ├── hooks.ts              # useEndpoint / useEndpointMutation wrappers over contract endpoints
│   └── *Page.tsx             # Lazy-loaded route views + colocated *.test.tsx & *.css
└── i18n/
    └── en-US.json            # Default locale keys (<id>.*) verified by `i18n` gate
```

## 3. Module Manifest (`module.ts`)

`defineModule` (`@bslt/contract`) validates every declaration at load time:

| Field          | Rule                                                                                                                     |
| -------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `id`           | Lowercase alphanumeric (`/^[a-z][a-z0-9]*$/`), matching directory name `main/modules/<id>`.                              |
| `summary`      | Non-empty human summary rendered into [`../reference/module-dag.md`](../reference/module-dag.md) and `DIRECTION.md`.     |
| `status`       | `'stable' \| 'beta' \| 'experimental'`.                                                                                  |
| `dependsOn`    | Direct upstream `ModuleDefinition`s. Must form a strict DAG; projection modules may never appear in `dependsOn`.         |
| `endpoints`    | Record of `Endpoint` definitions (`@bslt/contract`). Error codes must start with `<id>.`.                                |
| `events`       | Record of `EventDef`s (`<id>.<noun>.<verb>`). Every declared event must have a `.publish(...)` call in `server/`.        |
| `jobs`         | Record of `JobDef`s (`<id>.<job>`). Every declared job must have a handler in `implementServer`.                         |
| `tables`       | Owned Postgres tables in `public`, each equal to `<id>` or starting with `<id>_`.                                        |
| `permissions`  | Optional `<id>.<perm>` strings locked to append-only bit positions (0–62) in [`bslt.lock.json`](../../bslt.lock.json).   |
| `flags`        | Optional `<id>.<flag>` boolean defaults surfaced in `GET /api/platform/context` (`CapabilityProvider`).                  |
| `entitlements` | Optional `<id>.<entitlement>` keys checked by `entitlement:<key>` endpoint auth requirements.                            |
| `env`          | Optional `object({...})` schema (`@bslt/schema`) parsed from process env at server boot.                                 |
| `csp`          | Optional extra CSP sources (`connect-src`, `img-src`, `media-src`, `frame-src`, `worker-src`) merged by `bslt sync csp`. |
| `web`          | Optional `false` for headless/server-only modules (`entitlements`, `search`, `analytics`).                               |

## 4. Server Binding (`implementServer`)

`implementServer(manifest, factory)` (`@bslt/server-system/module-host`) binds the manifest to runtime implementations and enforces exhaustiveness at compile time:

- **`endpoints`**: One handler `(req) => Promise<Response>` per manifest endpoint. Path params, query strings, and request bodies are validated by `@bslt/schema` before the handler runs; responses are validated in development and test. Domain errors are thrown via `req.fail('CODE')`.
- **`jobs`**: One worker handler per declared `JobDef`, executed by `sys_jobs` workers (`PROCESS_ROLE=worker` or `media-worker`).
- **`cron`**: Named schedules (`ScheduleSpec`) persisted in `sys_cron_schedules` and enqueued onto `sys_jobs`.
- **`subscribers`**: Transactional outbox (`sys_outbox`) subscribers with idempotent keys (`runSubscriberTwice` test helper).
- **`channels`**: Realtime WebSocket channel authorizers (`deny-by-default`).
- **`verifiers`**: Raw-body webhook signature verifiers (`auth: { webhook: '<key>' }`).
- **`context` / `requirements`**: Contributions to `GET /api/platform/context` and custom endpoint requirement guards (e.g. `tos.accepted`, `age.verified:<n>`, `entitlement:<key>`).
- **`privacy` / `actions` / `notificationKinds`**: Plug-in slots consumed by `compliance` (GDPR export/erase/anonymize), `moderation` (enforcement actions), and `notifications` (delivery channels & user preferences).
- **`api`**: Typed synchronous/async service port exposed only to downstream modules that declare this module in `dependsOn`.

---

## 5. Web Binding (`implementWeb`)

`implementWeb(manifest, spec)` (`@bslt/web-platform`) contributes UI surfaces assembled via runtime `flatMap` over installed modules (`createWebApp`):

- **`routes`**: Typed route descriptors (`shell: 'public' | 'auth' | 'app' | 'admin'`, `auth`, `flag`, `lazyPage(...)`). Public routes with `prerender: true` render through `AnonymousSdk` (`cache.public` endpoints only, enforced by `ssr-public-only`).
- **`nav`**: Navigation items placed into `app.primary`, `app.secondary`, `admin`, or `footer` slots.
- **`settings` / `admin` / `dashboard` / `palette`**: Declarative tabs, cards, and command-palette actions.
- **`messages`**: Lazy loader for `../i18n/en-US.json`.

---

## 6. Dependency & Boundary Rules

Enforced by `eslint-plugin-boundaries`, `module-graph`, and `module-shape`:

1. **Strict DAG:** Module A may import `@bslt/B/contract` or consume `deps.B` on the server **only** if `A` lists `B` in `dependsOn`.
2. **Subpath encapsulation:** No package outside `main/modules/<id>/` may import `@bslt/<id>/server` except `main/apps/server/src/generated/modules.ts`, nor `@bslt/<id>/web` except `main/apps/web/src/generated/modules.ts`.
3. **Projection decoupling:** Projection modules (`audit`, `notifications`, `webhooks`, `analytics`) observe producers via outbox event metadata and subscribe without reverse `dependsOn` edges.
4. **Foreign-key alignment:** Cross-module SQL foreign keys must match `dependsOn` edges in `module.ts`.

## 7. Recipe: Adding a New Feature Module

Scaffold a complete vertical slice with one command:

```bash
pnpm bslt module new <id>
```

Then complete your domain slice:

1. Edit `main/modules/<id>/server/migrations/0001_<id>.sql` (`<id>_` table names + `SELECT sys_apply_rls(...)`), apply against scratch Postgres, and refresh catalog + rows:
   ```bash
   pnpm bslt db catalog && pnpm bslt sync rows
   ```
2. Define combinator schemas in `contract/schemas.ts`, error codes in `contract/errors.ts`, and endpoints in `contract/endpoints.ts`.
3. Write failing colocated unit tests (`*.test.ts`, `*.test.tsx`) and real-DB RLS isolation tests (`describeOwnerIsolation`) before implementing `server/` and `web/`.
4. Refresh derived artifacts and snapshots:
   ```bash
   pnpm bslt sync modules
   pnpm bslt sync permissions
   pnpm bslt sync openapi
   pnpm bslt sync docs
   pnpm bslt snapshot api
   pnpm bslt snapshot web-routes
   ```
5. Verify with `pnpm bslt gate merge --concurrency=2`.

See [`../dev/module-creation.md`](../dev/module-creation.md) for the step-by-step developer walkthrough and [`../reference/module-dag.md`](../reference/module-dag.md) for the live module graph.
