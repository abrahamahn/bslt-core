## 1. Platform Posture (`foundation-v1`)

BSLT completed its 21-phase modular restructure (`Phases 0–20`) and is tagged **`foundation-v1`**. It is a clone-and-own TypeScript SaaS and platform foundation built around five invariants:

1. **12 Kernel Packages + Vertical Modules (`main/modules/<id>/`).** All horizontal legacy packages (`main/shared`, `main/server/core`, `main/client/api`) are gone and tombstoned. Every domain feature owns its contract, SQL migrations, generated row bindings, server service/repository, web pages/hooks, and `en-US` copy in one folder registered in [`bslt.config.ts`](../bslt.config.ts).
2. **Owned Runtime Stack (`[react, react-dom]` only).** `deps-allowlist` enforces zero third-party npm runtime dependencies outside React. The HTTP router (`node:http`), PostgreSQL v3.0 wire driver & pool (`@bslt/protocols/pg`), S3 SigV4 (`@bslt/protocols/s3`), Valkey/Redis RESP (`@bslt/protocols/resp`), RFC 6455 WebSocket (`@bslt/protocols/ws`), RFC 8291 WebPush (`@bslt/protocols/webpush`), RFC 6238 TOTP (`@bslt/protocols/totp`), CBOR/COSE/WebAuthn (`@bslt/protocols/{cbor,cose}`), Multipart (`@bslt/protocols/multipart`), OTLP/HTTP (`@bslt/protocols/otlp`), schema validator (`@bslt/schema`), and UI component system (`@bslt/ui`) are 100% owned and tested in-repo.
3. **One Flat `public` Schema with Forced RLS & Locked Migrations.** Every table is prefixed by its owning module (`<id>_*` or `sys_*`), classified via `sys_apply_rls`, executed under least-privilege roles (`bslt_app`, `bslt_worker`, never `BYPASSRLS`), and protected by immutable migration SHA-256 checksums in [`bslt.lock.json`](../bslt.lock.json).
4. **Public-Only Prerender, SPA App Shells.** Public marketing, legal, pricing, support, and status pages prerender through `AnonymousSdk` (`cache.public` endpoints only, enforced by `ssr-public-only`). Authenticated `/app` and `/admin` routes render strictly client-side via `CapabilityProvider` (`GET /api/platform/context`).
5. **Two Workflows & In-Network Operations.** `.github/workflows/` contains exactly `ci.yml` and `deploy.yml`. Production servers boot by `PROCESS_ROLE` (`api | realtime | worker | media-worker | all`), export Prometheus metrics + optional OTLP/HTTP traces/metrics (`OTEL_EXPORTER_OTLP_ENDPOINT`), deploy alert rules (`alerts.yml`), and run in-VPC `AES-256-GCM` encrypted backups + PITR WAL archiving with automated restore drills (`infra/runtime/backup/`).

## 5. Adopting & Extending After `foundation-v1`

1. **Rename identity defaults:** `pnpm bslt rename "<Your Product>"` (see [`dev/rename.md`](./dev/rename.md)).
2. **Choose installed modules:** Edit [`bslt.config.ts`](../bslt.config.ts) to keep only the vertical modules your product needs, then run `pnpm bslt sync modules && pnpm bslt sync docs`.
3. **Add your first domain module:** Run `pnpm bslt module new <id>` and follow [`specs/modules.md`](./specs/modules.md).
4. **Configure production secrets & backups:** Follow [`deploy/README.md`](./deploy/README.md), [`deploy/production-postgres.md`](./deploy/production-postgres.md), and [`deploy/backup-restore.md`](./deploy/backup-restore.md).
