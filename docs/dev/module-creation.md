# Module Creation Guide

BSLT features live as self-contained vertical modules under `main/modules/<id>/` (`@bslt/<id>`). Look at `main/modules/tasks/` for the canonical reference module.

## Quick Start

```bash
# Preview the files that will be created without touching disk
pnpm bslt module new notes --dry-run

# Scaffold, register in bslt.config.ts, sync composition files, install, and build
pnpm bslt module new notes
```

`<id>` must be a lowercase alphanumeric identifier (`/^[a-z][a-z0-9]*$/`, e.g., `notes`, `projects`, `bookmarks`) that does not collide with an existing module or reserved kernel/package name.

## What Gets Generated

`pnpm bslt module new <id>` creates a complete, tested, RLS-protected module package and wires it through `bslt.config.ts`:

```text
main/modules/<id>/
├── package.json                      # @bslt/<id> with ., ./contract, ./server, ./web exports
├── tsconfig.json                     # Composite TypeScript config
├── vitest.config.ts                  # Colocated Vitest config
├── README.md                         # Module overview + generated metadata block
├── module.ts                         # defineModule({ id, version, dependsOn, endpoints, errors })
├── module.test.ts                    # Manifest tests
├── contract/
│   ├── schemas.ts                    # @bslt/schema request/response schemas + inferred types
│   ├── schemas.test.ts
│   ├── errors.ts                     # defineErrors('<id>', { ... })
│   ├── errors.test.ts
│   ├── endpoints.ts                  # endpoint({ method, path, auth, params, body, response, ... })
│   ├── endpoints.test.ts
│   └── index.ts                      # Explicit named contract exports
├── server/
│   ├── migrations/
│   │   └── 0001_<id>.sql             # Owned table + FK to users(id) + sys_apply_rls(...)
│   ├── generated/
│   │   └── rows.ts                   # Generated by `bslt sync rows` from catalog.snapshot.json
│   ├── repository.ts                 # Typed SQL queries via @bslt/db
│   ├── repository.test.ts
│   ├── repository.real-db.test.ts    # Real-DB CRUD + describeOwnerIsolation RLS suite
│   ├── service.ts                    # Pure domain mapping & business rules
│   ├── service.test.ts
│   ├── handlers.ts                   # implementServer(<id>Module, { handlers })
│   ├── handlers.test.ts
│   └── index.ts                      # Explicit named server export (<id>Server)
├── i18n/
│   └── en.json                       # Flat translation messages
└── web/
    ├── hooks.ts                      # useEndpoint / useEndpointMutation hooks
    ├── hooks.test.tsx
    ├── <Pascal>Page.tsx              # Accessible @bslt/ui page component
    ├── <Pascal>Page.test.tsx
    ├── index.tsx                     # Explicit named web export (<id>Web, hooks, page)
    └── index.test.tsx
```

The command also:

1. Appends `<id>Module` to `bslt.config.ts`.
2. Runs `bslt sync modules` to update `main/apps/{server,web}/src/generated/modules.ts`, `package.json` dependencies, Dockerfiles, `main/tools/generated/module-graph.json`, and the module `README.md` block.
3. Updates `main/kernel/db/catalog.snapshot.json` and runs `bslt sync rows` to emit `server/generated/rows.ts`.
4. Updates TypeScript project references (`bslt sync ts`), file headers (`bslt sync headers`), generated reference docs (`bslt sync docs`), route/API snapshots (`bslt snapshot api`, `bslt snapshot web-routes`), and the OpenAPI document (`bslt sync openapi`).

## Architectural Rules Enforced by Gates

Every module under `main/modules/<id>/` is checked in `pnpm bslt gate merge` by `module-shape`, `module-graph`, `test-pairs`, `unused-exports`, `raw-sql-outside-repos`, and ESLint boundary rules:

- **Strict import boundaries:** Modules may import only `@bslt/*` kernel packages (`@bslt/schema`, `@bslt/contract`, `@bslt/db`, `@bslt/server-system`, `@bslt/client-engine`, `@bslt/react`, `@bslt/ui`, `@bslt/web-platform`) and public subpaths of modules declared in `dependsOn` (e.g., `dependsOn: ['identity']` when referencing `users(id)`). Never import `@bslt/shared`, `@bslt/core`, `@bslt/api`, or `main/apps/*`.
- **Subpath isolation:**
  - `contract/` imports only `@bslt/schema`, `@bslt/contract`, and `dependsOn` `./contract` subpaths.
  - `server/` never imports client/React/UI packages or `./web`.
  - `web/` never imports server/DB packages or `./server`.
- **No hand-written client wrappers:** `useEndpoint` and `useEndpointMutation` from `@bslt/react` infer paths, params, bodies, responses, and cache invalidation directly from `<id>Module` endpoints.
- **Database ownership & RLS:** Every table created in `server/migrations/*.sql` must declare row-level security via `sys_apply_rls(...)` or `sys_apply_audience(...)`, and every foreign key to another module's table requires that module in `dependsOn`.

## Customizing a New Module

1. **Edit schemas & endpoints** in `main/modules/<id>/contract/schemas.ts`, `errors.ts`, and `endpoints.ts`.
2. **Update the SQL baseline** in `main/modules/<id>/server/migrations/0001_<id>.sql`.
3. **Refresh the DB catalog & generated row types** against your local Postgres instance:
   ```bash
   pnpm bslt db reset --force
   pnpm bslt db catalog
   pnpm bslt sync rows
   ```
4. **Update repository, service, handlers, and web UI** alongside their colocated `*.test.ts(x)` and `repository.real-db.test.ts` suites (keeping ≥ 60% failure-state assertions).
5. **Refresh docs & snapshots** if endpoints or routes changed:
   ```bash
   pnpm bslt sync docs
   pnpm bslt snapshot api
   pnpm bslt sync openapi
   pnpm bslt snapshot web-routes
   ```
6. **Verify gates:**
   ```bash
   pnpm bslt gate merge
   pnpm test:real-db
   ```
