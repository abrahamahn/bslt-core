**Colocated test coverage — 340 files, ratcheted.**
`bslt gate run test-pairs` gates against `test-pairs-debt.json`, a shrink-only
list: a new untested source file fails, and adding a test lets its entry be
dropped. 143 in `server/core`, 88 in `apps/web`, 27 in `server/db`. Lower it
with `pnpm bslt gate run test-pairs --update` as tests land.

Worth reading before spending on it: of the files on that list, most are already
exercised by the integration suites and lack only a _colocated_ peer, and the
scan is ~58% false-positive at symbol granularity (it excludes the defining
file, so an internally-used export reads as dead). The useful target is the
subset where an absent test is actually dangerous, not the count.

(created by `0301_email.sql`) with no code reading them since the email

CI has not succeeded in 100+ runs (back to 2026-07-08) and `Deploy` is gated on
`workflow_run.conclusion == 'success'`, so it skipped 60/60. Clearing the budget
is the single fix that unblocks both CI and auto-deploy; the trigger now points
at `main`, so a push will deploy once it is clear.

**CI jobs that fail for their own reasons.** The one run that executed today
(before the budget ran out) failed `real-db-gate`, `coverage-report`,
`e2e-tests` and `lighthouse`. Undiagnosed — several are plausibly
environment-dependent (real-DB needs a provisioned database, e2e needs servers,
lighthouse needs a deployed URL) rather than broken code. Worth working through
before assuming the budget alone makes CI green.

**`git push` exits 141 (SIGPIPE) with the pre-push hook enabled.** The gate
itself passes: `infra/git-hooks/pre-push` run standalone with a synthetic ref
line exits 0 after printing "✅ Pre-push passed", and lint/type-check/test are
8/8. Only `--no-verify` pushes succeed. **Note:** commit `ec76ccad` claims the
undrained-stdin `break` was the cause and it is not — the next push failed
identically, with cache misses, which also refutes the "only when FULL TURBO"
reasoning in that message. Draining stdin is still correct for a pre-push hook,
but the real cause is unidentified; do not trust that commit message.

## Closed 2026-08-04/05

**Dead classes: zero.** `dead-classes-debt.json` is `{}` — the ratchet has
nothing left to carry. §5.4.3 found 448 of them; billing, settings, the design
system, the demo pages and the remaining feature components are all clear. There
is no Tailwind in this repo, so an undefined class renders as nothing while the
markup reads as though the intent were satisfied; `pnpm bslt gate run dead-classes` now
fails on the first new one rather than on a ceiling.

**Undefined CSS custom properties: zero.** A `var()` naming a token nothing
defines drops the whole declaration, as silently as a dead class. A sweep of
every `var(--ui-*)` against every definition found seven; four are
component-owned and correctly used with a fallback, and three were real bugs,
all fixed 2026-08-04: `--ui-color-surface-hover` and `--ui-color-subtle` left
the OAuth button, the file-input button and the side-peek close with **no hover
feedback at all**, and `--ui-color-text-on-primary` left skip-link and badge
text on a primary background with no colour of its own. Each was replaced with
what the sibling rule in the same stylesheet already uses.

`pnpm bslt gate run undefined-tokens` covers this category as of 2026-08-04, and
`pnpm lint:css` — all four CSS gates — now runs inside `bslt gate merge`. It never
had before, so the dead-class and responsive gates had been advisory since the
day they shipped.

**`TEMP(expires: 2026-08-31)` markers in `eslint.config.ts`.** The four
shared-layer ones are **resolved (2026-08-04)**: `system/errors`, `system/http`
and `db/pagination` are now boundary elements of their own, so `db`/`core`/
`comms`/`realtime` name what they actually import instead of being handed a
whole layer. The edges are narrower than the allowances they replaced — a new
`core -> system/http` import now fails, verified by mutation.

The eight server-package allowances are **legitimized (2026-08-04)**, rules
byte-identical, with the measurement recorded in the config: `shared-contracts`
is the ports layer (31 of 33 server imports are `import type`, erased at compile
time), and `shared-system` is the shared runtime vocabulary (server-core alone
imports it 101 times) — neither is debt to narrow.

The `client-react -> @bslt/api` edge is **legitimized (2026-08-05)**, closing
the last marker: `@bslt/api` is a declared dependency of `@bslt/react`, and
`client-engine` — the layer the DAG drew between them — exports storage, the
query cache, theme and key bindings, and no API clients at all. There was
nothing to route through. `principles.md` now draws `api` and `client-engine`
as siblings rather than a chain, which is what made a correct edge look like
debt.

**Zero `TEMP(...)` markers remain repo-wide.**
